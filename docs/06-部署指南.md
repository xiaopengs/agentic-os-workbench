# 06 · 部署指南（Agentic OS 自动化开发工作台）

> 适用架构：**方案 A** —— 源码态前后端分离（`frontend/` + `backend/` + `shared/`），部署态构建为自包含单元 `dist/`，统一部署到单个 EdgeOne Makers 项目。

---

## 一、架构与部署单元的关系

源码态关注点分离，部署态必须自包含（平台要求 `cloud-functions/` 与依赖声明位于部署单元根目录）：

```
源码态（开发）                     部署态（dist/ 由脚本生成）
├── frontend/    Next.js 16   →    ├── app/ components/ lib/ styles/ public/
├── backend/     业务实现      →    ├── backend/
├── shared/      共享契约      →    ├── shared/
├── cloud-functions/ 平台入口  →    ├── cloud-functions/api/[[default]].ts
└── scripts/build-deploy.mjs   →    └── package.json（前后端依赖合并）
```

相对路径一致性已保证：`cloud-functions/api/[[default]].ts` 内 `../../backend/...` 在 `dist/` 下解析为 `dist/backend/...`，与源码态一致，**无需改写导入**。

> ⚠️ `dist/` 是构建产物，不要手工编辑，不要提交到 Git（已在 `.gitignore`）。

## 二、前置条件

| 项 | 要求 | 检查命令 |
|---|---|---|
| Node.js | ≥ 20 | `node -v` |
| EdgeOne CLI | ≥ 1.6.7 | `edgeone -v` |
| 登录态 | 已授权 | `edgeone whoami` |
| 账号配额 | 项目数未达上限（通常 40） | 控制台查看 |

安装 CLI：
```bash
npm install -g edgeone@latest --registry=https://registry.npmmirror.com
```

登录（写入项目目录凭证，沙箱友好）：
```bash
edgeone login --site china --local      # 中国站
edgeone login --site global --local     # 国际站
```

## 三、环境变量

在 **Makers 控制台 → 项目 → 环境变量** 注入（本地开发写入 `.env.local`，该文件不提交）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `JWT_SECRET` | ✅ **是** | JWT 签名密钥（HS256）。生产环境缺失会直接返回 500 `SERVER_MISCONFIG`——**故意如此设计，杜绝硬编码密钥导致的安全事故**。建议 ≥32 位随机串 |
| `BLOB_STORE` | 否 | Blob 存储名称，不填用默认 |
| `KV_BINDING` | 否 | KV 绑定名；检测到时存储层自动优先走 KV，否则回退 Blob |

生成安全密钥：
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

> 后端已适配：优先读 `context.env`（平台注入），回退 `process.env`；非生产环境才允许固定值并打印警告。

## 四、构建部署单元

```bash
# 1) 生成 dist/（源码分离 → 部署单元）
node scripts/build-deploy.mjs

# 2) 安装合并后的依赖（前端 + 后端）
cd dist && npm install
```

构建脚本会：清理旧产物 → 复制前端源码到根 → 复制 `backend/ shared/ cloud-functions/` → 合并 `package.json` 依赖。

## 五、本地预览（推荐先做）

```bash
cd dist
edgeone makers dev --name <项目名> --skip-env-sync
```

- `--name` 用于关联**已存在**的远端项目，使 Blob/KV 等平台能力可用；
- `--skip-env-sync` **必须带**，否则会卡在"是否同步环境变量"的交互提示；
- 预览地址用 `http://127.0.0.1:8088`（**不要用 localhost**，沙箱 IPv6 链路异常会假 404）；
- 全新项目远端还不存在 → 需先 `edgeone makers deploy -n <项目名>` 创建一次，再回来跑 dev。

验证清单：
1. 打开首页应跳转 `/login`
2. 注册账号 → 自动登录 → 进入工作台
3. 新建工作流 → 刷新页面数据仍在（真实持久化）
4. 登出后再登录，数据一致

## 六、部署上线

```bash
cd dist
edgeone makers deploy -n <项目名> --json          # 生产环境
edgeone makers deploy -n <项目名> --json -e preview  # 预览环境
```

成功输出（末行为 JSON）：
```json
{"status":"success","url":"https://xxx.edgeone.cool?eo_token=...","projectId":"pages-xxx","consoleUrl":"https://..."}
```

> ⚠️ 访问地址**必须保留完整查询参数**（`eo_token`、`eo_time`），去掉会 401。

部署前**务必**确认控制台已注入 `JWT_SECRET`，否则所有鉴权接口会 500。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Missing: deployCredential` | 项目未 link | 用 `--name <已存在项目>` 或先 deploy 一次创建项目 |
| 接口 500 `SERVER_MISCONFIG` | 缺 `JWT_SECRET` | 控制台注入后重新部署 |
| 部署"成功"但访问 404 | 在项目上级目录执行了 deploy | 必须 `cd dist` 后再部署 |
| 页面按钮点了没反应 | Next 16 HMR 被判跨域 | `next.config.ts` 需含 `allowedDevOrigins: ['127.0.0.1']`（已配置） |
| 数据刷新后丢失 | 用了内存存储 | 存储层必须走 KV/Blob，禁止内存态 |
| 项目数超限 | 账号配额满（约 40） | 控制台清理旧项目，或复用已有项目 |

## 八、回滚

Makers 控制台 → 项目 → 部署历史 → 选择上一版本回滚。建议每次上线前记录 `deploymentId`。
