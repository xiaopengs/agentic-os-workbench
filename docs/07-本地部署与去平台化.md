# 07 · 本地最小化部署与去平台化

> 结论先行：**这个项目对 EdgeOne 的依赖完全可以去掉**。平台耦合只集中在 5 个薄适配点上，
> 业务代码（鉴权、配额、审计、CRUD、AI 流式）没有一行是平台专属的。

---

## 一、为什么原本会依赖 EdgeOne

不是设计需要，而是**部署目标选择**带来的。逐一拆解耦合点：

| # | 耦合点 | 是否平台专属 | 解耦方式 |
|---|---|---|---|
| 1 | `cloud-functions/api/[[default]].ts` 的 `onRequest(context)` 契约 | 是 | 新增 `backend/adapter/node.ts`，把 Node `(req,res)` 翻译成同样的 `context`，**业务代码零改动复用** |
| 2 | KV / Blob 存储 | 是 | `store.ts` 新增**本地文件驱动**（`LOCAL_STORE=file`），且平台 SDK 不可用时自动兜底 |
| 3 | `context.env` 读环境变量 | 否 | `env.ts` 本就支持 `context.env → process.env` 兜底 |
| 4 | AI Gateway（自动注入凭据） | 是 | 缺凭据时返回 503 `AI_UNAVAILABLE` 优雅降级，不崩溃；自托管换任意 OpenAI 兼容端点即可 |
| 5 | `edgeone` CLI 部署 | 是 | 本地直接 `node` 起服务，无需 CLI、无需登录 |

**关键点**：后端自始至终就做了存储驱动抽象（`StoreDriver` 接口：KV / Blob），所以第 2 项的解耦只是**再加一个驱动实现**，上层 `kv.ts` 毫无感知——这就是当初做抽象的价值。

## 二、本地最小化部署（一条命令）

```bash
node scripts/start-local.mjs
```

启动两个进程：

| 服务 | 地址 | 说明 |
|---|---|---|
| 后端 API | http://127.0.0.1:8787/api | Node 标准库 HTTP 服务，**零框架、零平台 SDK** |
| 前端应用 | http://127.0.0.1:3000 | Next.js，API 指向 8787 |

- 数据落在 `./.data/store.json`（纯文本，可直接查看/编辑；删除即重置）
- 停止：`Ctrl+C`（两个子进程一并退出）
- 端口可用 `API_PORT` / `WEB_PORT` 覆盖

### 单独启动（便于调试）

```bash
# 仅后端
PORT=8787 LOCAL_STORE=file npx tsx backend/adapter/server.ts

# 仅前端
cd frontend && NEXT_PUBLIC_API_BASE=http://127.0.0.1:8787/api npx next dev -p 3000
```

## 三、环境变量（本地）

| 变量 | 本地默认值 | 说明 |
|---|---|---|
| `LOCAL_STORE` | `file` | 使用本地 JSON 文件持久化 |
| `LOCAL_STORE_PATH` | `.data/store.json` | 数据文件路径 |
| `PORT` | `8787` | 后端端口 |
| `JWT_SECRET` | 未设时用开发固定值并告警 | **自托管生产必须设置 ≥32 位随机串** |
| `NEXT_PUBLIC_API_BASE` | `http://127.0.0.1:8787/api` | 前端 API 基址（同域部署时为 `/api`） |
| `LOCAL_AI_MOCK` | `1`（一键脚本默认） | 未配 AI Gateway 时用本地模拟 SSE 流 |

生成安全密钥：`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`

### AI Copilot 的本地降级

AI 是唯一"天然需要外部服务"的能力，本地有两档处理：

| 场景 | 行为 |
|---|---|
| 配了 `AI_GATEWAY_API_KEY` / `AI_GATEWAY_BASE_URL` | 走真实模型（OpenAI 兼容 `/chat/completions`），本地云端行为一致 |
| 未配 + `LOCAL_AI_MOCK=1` | 走 `openLocalMockChat()`，产出与 OpenAI **完全同构**的 SSE 帧，逐 token 推送；配额扣减、审计落库、前端流式渲染全链路照常 |
| 未配 + 未开 mock | 返回 `503 AI_UNAVAILABLE`（不是 500 崩溃），错误文案直接给出两种修复路径 |

关键点：mock 发的是标准 `data: {"choices":[{"delta":{"content":"…"}}]}` 帧，
所以 `iterChatStream()` 与前端渲染代码**一行都不用改**——换真模型只需改环境变量。

## 四、两种部署形态对照

| | 平台部署（EdgeOne Makers） | 本地 / 自托管 |
|---|---|---|
| 启动 | `edgeone makers deploy` | `node scripts/start-local.mjs` |
| 后端运行时 | Cloud Functions + `onRequest(context)` | Node HTTP + `adapter/node.ts` |
| 存储 | KV（优先）/ Blob | 本地 JSON 文件（可换 SQLite/Postgres） |
| API 路径 | 同域 `/api/*` | `http://127.0.0.1:8787/api` |
| 需要登录 | 是 | **否** |
| 适用 | 公网交付、免运维 | 本地开发、内网自托管、私有化交付 |

> 前端代码两种形态完全一致，只需切换 `NEXT_PUBLIC_API_BASE`。

## 五、自托管到生产（可选进阶）

本地文件驱动适合单机；要多实例或更大规模，替换 `StoreDriver` 实现即可：

```ts
// backend/lib/store.ts 中新增一个驱动，实现 get/put/del/list 四个方法
// 例如 SQLite / Redis / Postgres，上层 kv.ts 无需任何改动
```

生产建议：
- 用 `pm2` 或 systemd 守护进程
- 前端 `next build && next start`（而非 `next dev`）
- 设置强 `JWT_SECRET`，并置于反向代理（Nginx）之后启用 HTTPS
- 跨域直连时后端已支持 CORS；更推荐用 Nginx 将 `/api` 反代到后端，实现同域

## 六、验证结果

| 测试 | 结果 |
|---|---|
| 后端冒烟（脱离平台，mock KV） | **34/34 通过** |
| 端到端（真实浏览器，前端 3000 + 后端 8787） | **22/22 通过** |
| 本地 AI 模拟流（curl 实测 SSE） | **通过**（逐 token 增量 + usage 回执 + `[DONE]`） |

端到端覆盖：未登录拦截 → 注册 → 弱密码 400 → 重复注册 409 → 登录 → 创建工作流 →
持久化校验 → 更新 → Trace → 用量 → 审计 → 删除 → 无效 token 401 → 登出失效 → 零 JS 错误。
