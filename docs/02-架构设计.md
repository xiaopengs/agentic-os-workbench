## 1. 总体架构

工作台采用**单文件 HTML 五层架构**，自上而下单向依赖，严禁反向调用：

```
┌──────────────────────────────────────────────────────────────┐
│  L1 视图层（静态 HTML + CSS）                                  │
│  顶部导航 / 左侧边栏 / KPI 卡 / Lifecycle / Simulation Lab     │
│  / Live Trace / Recent Workflows / 右侧栏四卡片 / 能力域占位页  │
├──────────────────────────────────────────────────────────────┤
│  L2 渲染层（render* 系列函数，纯函数式：读状态 → 写 DOM）        │
│  renderKpi · renderLifecycle · renderSimLab · renderTrace     │
│  renderWorkflows · renderCopilot · renderAttention            │
│  renderNextStep · renderRelease · renderSyncBadge             │
├──────────────────────────────────────────────────────────────┤
│  L3 状态与模拟引擎层（State + 引擎定时器）                       │
│  state 对象（唯一可变状态源）+ tick 时钟/trace 流/进度推进/流转  │
├──────────────────────────────────────────────────────────────┤
│  L4 数据接入层（DataBridge）                                   │
│  资料库 SDK（query/addRecord）⇄ localStorage 缓存 ⇄ 内置演示数据 │
├──────────────────────────────────────────────────────────────┤
│  L5 宿主层：WorkBuddy 资料库（数据表存储 + 页面托管 + 发布）      │
└──────────────────────────────────────────────────────────────┘
```

**核心原则**：
- **状态单一源**：所有动态数据收敛于 `state` 对象，渲染层只读 state，不持有状态
- **单向调用链（DAG）**：事件处理 → 修改 state → `refreshAll()` → 各 render 函数独立渲染。渲染函数之间**零互调**
- **全内联零外链**：CSS/JS/图标全部内联；图表（环形进度、Canary 圆环、进度条、波浪装饰）用内联 SVG 手写；图标用内联 SVG path

## 2. 技术选型与约束

| 维度 | 选型 | 理由 |
|---|---|---|
| 页面形态 | 单文件 HTML（约 3500-4000 行） | 资料库托管 + 发布即可公网访问；零运维 |
| 样式 | 原生 CSS（CSS Variables 设计令牌） | 无框架依赖，可控性最高 |
| 图标 | 内联 SVG symbol + `<use>` | 一份 path 复用多处，体积小 |
| 图表 | 手写 SVG（circle stroke-dasharray 环形进度） | 铁律 3：禁外部图表库 |
| 数据 SDK | `window.__SMART_PAGE__.database`（资料库注入） | 在线存储与双向同步的官方通道 |
| 降级链路 | SDK → localStorage → 内置演示数据 | 保证任何环境打开不白屏 |
| JS 风格 | ES5（var/function，SDK 相关代码强制） | 兼容宿主注入环境；IIFE 封装 |

## 4. 函数调用链设计（DAG，铁律 9）

### 4.1 调用关系图（箭头 = 调用方向，无环）

```
DOMContentLoaded
  └→ init()
       ├→ loadState()            [L4: localStorage 恢复]
       ├→ DataBridge.init()      [L4: SDK 探测 → 表数据拉取/降级]
       │    └→ (async) 合并表数据到 state → refreshAll()
       ├→ bindEvents()           [一次性事件绑定]
       ├→ Engine.start()         [L3: 启动 3 个定时器]
       └→ refreshAll()           [首次渲染]

事件处理器（用户交互入口，唯一允许写 state 的层）
  onNavClick → switchPage
  onReplayDag → Engine.replay() → refreshAll
  onRunWorkflow → DataBridge.addWorkflow → refreshAll
  onCopilotBtn → openCopilot → appendCopilotMsg
  onBellClick → toggleBellDropdown

refreshAll()（统一刷新入口，唯一调度者）
  ├→ renderKpi()          ─┐
  ├→ renderLifecycle()     │
  ├→ renderSimLab()        │  各渲染函数独立读 state，
  ├→ renderTrace()         │  互相零调用
  ├→ renderWorkflows()     │
  ├→ renderNextStep()      │
  ├→ renderRelease()       │
  └→ renderSyncBadge()    ─┘

Engine（模拟引擎，3 个独立定时器）
  tickClock(1s)   → state.traceClock++ → renderTrace 内时钟 span 更新*
  tickTrace(4s)   → state.traces.unshift + DataBridge.addTrace(异步) → refreshAll
  tickProgress(2s)→ state.simProgress / state.nextStep / state.canary 推进 → refreshAll
```

> *时钟每秒更新走局部 DOM 更新（`updateClock()` 只改一个 text 节点），不触发全量 refreshAll，避免每秒重绘整页。

### 4.2 环路防护要点

- `renderSimLab()` 不调 `renderTrace()`；`renderTrace()` 不调任何 render —— 二者的联动由 `tickTrace` 事件处理器统一调度
- `DataBridge.addTrace/addWorkflow` 是**写通道**，返回 Promise 后由调用方决定是否 `refreshAll()`，数据层不直接触渲染
- `switchPage()` 只改 `state.activePage` + 切换 display，不调用内容渲染函数（各页面内容为静态或由 refreshAll 覆盖）

## 5. 数据流设计

### 5.1 双表结构（资料库数据表）

**表 W「AgenticOS 工作流」**（承载 Recent Workflows 区）

| 字段 | 类型 | 说明 |
|---|---|---|
| 工作流名称 | text | 主标识 |
| 分类 | text | 如 手机↔电脑·文件同步 |
| 描述 | text | 副标题 |
| 设备数 | number | 3/4/2 |
| 步骤数 | number | 12/8/6 |
| 覆盖率 | number | 96/93/90 |
| 回归时长分 | number | 18/22/30 |
| 状态 | select | 运行中/已完成/失败 |
| 更新时间 | date | 排序字段 |

**表 T「AgenticOS Trace 记录」**（承载 Live Trace 区）

| 字段 | 类型 | 说明 |
|---|---|---|
| Span类型 | select | Agent/Skill/Tool/Contract |
| Span名称 | text | task_router / file_transfer / … |
| 耗时ms | number | 48-200 |
| 状态 | select | Success/Failed/Running |
| 时间戳 | text | HH:MM:SS 展示值 |

### 5.2 同步策略

```
启动：getSchema(取 select options) → query(按更新时间倒序，pageSize 上限分页拉全量)
      → state.workflows / state.traces 覆盖 → refreshAll()
写入：模拟引擎新 trace → addRecord（异步火忘，失败仅记 console + 同步徽标降级）
      用户运行新工作流 → addRecord → 成功后本地插入 state 首位 → refreshAll()
离线：SDK 不可用 → 全部降级为 localStorage 持久化 + 内置演示数据，徽标显示「离线模式」
QPS 防护：trace 写入节流（≥4s/次）；无并行突发 query
```

### 5.3 绑定标记（DSDK011/012）

所有由 `renderData` 写入的承载文本的最内层元素，同时设置：
`data-sp-bindable="database"` + `data-sp-database-id="<对应表ID>"`（工作流区用表 W id，trace 区用表 T id）。

## 6. 响应式布局架构

```
grid-template:
  "topnav topnav topnav" 60px
  "sidenav main  aside"  1fr / 208px 1fr 328px     ← ≥1280px

1280px> 窗口 ≥900px：aside 下移至 main 之后（两栏 grid，aside 变横向卡片流）
<900px：单列；sidenav 收起为汉堡抽屉（顶部导航左侧按钮触发）
        KPI 卡 4→2 列；Lifecycle 6 节点纵向排列；底部安全区 env(safe-area-inset-bottom)
```

移动端硬性要求：按钮点击区 ≥44×44px；输入框字号 ≥16px（防 iOS 缩放）；表格类内容无横向溢出。

## 7. 降级与容错

| 场景 | 行为 |
|---|---|
| `window.__SMART_PAGE__` 不存在（本地直开） | DataBridge 进入离线模式；工作流/trace 用内置演示数据（与设计稿数值一致）；localStorage 保存 AI 面板历史与运行状态 |
| SDK query 失败 | 捕获 → console.warn → 使用演示数据 → 徽标「离线模式」 |
| addRecord 失败 | 本地仍插入（保证 UI 连续性），徽标短暂显示「同步失败」后回退 |
| localStorage 不可用（隐私模式） | try/catch 静默降级为内存态 |
| 首次打开无表数据 | 预置 3 条工作流 + 4 条 trace 演示数据（与设计稿一致），保证非空首屏（铁律 6） |

## 8. 页面写入策略（铁律 7③）

单文件体量超限 → 先写**骨架**（完整 CSS + 全部 HTML 结构 + 占位 script 入口），再按模块增量写入 JS：
第 1 批：状态与工具函数 + DataBridge；第 2 批：模拟引擎 + 渲染函数；第 3 批：事件绑定 + AI 面板 + 初始化。
每批写入后文件保持可运行。
