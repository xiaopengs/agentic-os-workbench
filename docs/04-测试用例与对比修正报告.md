3. **能力域 5 子页为占位实现**：按分期方案属 Phase 2 范围，本期提供导航可达 + 能力卡说明。

### 9.4 本轮修复的真实缺陷

| 缺陷 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 错误响应缺 CORS 头 | 跨域下前端拿不到 401/402/409 的真实错误码，只看到不透明失败 | `origin` 解析写在 `guard()` 内部，异常响应绕过 CORS 附加逻辑 | 把 origin 解析与 CORS 附加**上移到 guard 之外**；Node 适配器异常分支同步补 CORS |
| CORS 白名单漏自定义头 | 本地 AI 对话报「网络异常」，但后端直接 curl 正常 | 前端会带 `makers-conversation-id` 请求头，触发预检，而 `Access-Control-Allow-Headers` 只放行了 `Content-Type,Authorization` | 两处白名单（router + node adapter）补上该头 |
| E2E 参数拼接错误 | 传入 `.../api` 时所有请求变成 `/api/api/...` 全 404 | 用例路径自带 `/api` 前缀，与传入基址叠加 | 传入地址尾部 `/api` 统一剥离 |
| 平台 SDK 强依赖 | 本地未装 `@edgeone/pages-blob` 时功能受限 | 该包在 `dependencies` 中 | 降为 `optionalDependencies`；`store.ts` 动态 import + 失败兜底 |

### 9.5 与 Phase 0 的对比

| 维度 | Phase 0（原型） | Phase 1（当前） |
|---|---|---|
| 测试是否依赖平台 | 是（资料库 SDK / lint 工具） | **否** |
| 数据真实性 | 浏览器内模拟 | **服务端持久化，刷新仍在** |
| 可断言范围 | 视觉 + DOM + localStorage | **视觉 + DOM + 真实 HTTP 全链路** |
| 测试套件 | 72 项静态对比修正 | 34（后端）+ 22（端到端）= **56 项自动断言** |
| 每次改动可验证性 | 需登录平台 | **一条命令本地跑通** |

> 这一节的意义：Phase 1 的测试**不再需要平台账号**，因此每次改动都能立刻验证——
> 这是去平台化带来的最直接收益，也是后续迭代速度的基础。

