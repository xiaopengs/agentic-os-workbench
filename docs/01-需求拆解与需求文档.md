## 1. 项目背景与定位

本项目为 **Agentic OS 自动化开发工作台**（Automation Workbench）——面向 Agentic OS 研发全角色的统一自动化开发平台，覆盖「意图 → Skill → Agent → 编排 → 端侧执行 → 安全 → 可观测」全链路。

工作台的三大核心定位（源自原始需求方案）：

| 定位 | 从 | 到 |
|---|---|---|
| 系统能力接入 | 人工逐应用对接 MCP/AppFunction | 声明式 Contract 注册 + 自动适配 |
| 测试验证 | 真机刷机 + 手动操作（反馈以天计） | 云端仿真自动化（回归 ≤30 分钟） |
| Skill 发布 | OTA 发版依赖 | 热更新可信管道（安全验证 + 灰度） |

## 2. 原始需求拆解分析

### 2.1 七大矛盾 → 七大能力域映射

| # | 核心矛盾 | 对应能力域 | 落地载体（工作台页面） |
|---|---|---|---|
| 一 | 系统能力接入慢（N 应用 N 次适配，依赖 OTA） | 域一：声明式能力接入与自动适配 | 顶部导航「能力接入」+ 左栏 Contract Registry |
| 二 | 工具不统一，上下文频繁丢失 | 域二/域五：仿真测试 + 可观测性 | 「仿真测试」「Trace」入口，总览页 Live Trace |
| 三 | 跨部门协同成本高（Contract 无统一平台） | 域七：跨部门协作与 DevOps 集成 | Contract Registry、跨角色工作流 |
| 四 | 测试验证周期长（真机手动，反馈以天计） | 域二：仿真测试与自动化验证 | 总览页 Simulation Lab、场景测试、真机集群 |
| 五 | 安全合规验证滞后（发布前才检查） | 域四：热更新安全验证管道 | 右栏 Trusted Release、安全入口 |
| 六 | 端侧模型调试困难（NPU/内存/功耗无法复现） | 域三：端侧 Runtime 开发支撑 | 总览页 Simulation Lab 的 Memory/NPU/P95/Power 指标 |
| 七 | Skill 热更新缺乏可信验证 | 域四：Skill 热更新开发与可信发布 | Trusted Release（安全扫描→兼容性→灰度） |

### 2.2 从设计稿（截图）反推的功能清单

设计稿为总览 Dashboard（Automation Workbench），包含八大功能区：

1. **顶部导航栏**：品牌 Logo、6 个一级导航（工作台/能力接入/仿真测试/端侧 Runtime/安全合规/发布运营）、全局搜索、环境选择器（Dev）、通知、头像
2. **左侧边栏**：10 个二级导航（总览/Contract Registry/Skills/Agents/场景测试/真机集群/Trace/安全/发布/知识库）+ 品牌卡
3. **KPI 统计卡片区**：Contract 128、Skills 486、Running Tests 24、Devices 16，含环比趋势
4. **Agent Lifecycle 流程区**：Intent → Contract → Skill → Agent → Simulation → Secure Release 六节点流水线，每节点含图标、双行说明、状态标签（已完成/Mock Ready/24 tests/进行中/Canary 10%）
5. **Simulation Lab**：端侧仿真（手机模型 + Memory 1.8GB/NPU 72%/P95 184ms/Power 1.2W 四指标）+ 测试进度（编译构建/单元测试/性能测试/场景回归/结果分析）+ 运行计时 + Replay DAG
6. **Live Trace**：实时调用链路（Agent/Skill/Tool/Contract 四类 Span，含时间戳、耗时、状态条）
7. **Recent Workflows**：最近工作流卡片（跨设备文件流转/日程冲突自动处理/外卖点单 Agent），含设备数、步骤数、覆盖率、回归时长、进度条
8. **右侧栏**：AI Copilot（4 个快捷操作）、Attention（3 条告警通知）、Next Step（4 步任务流）、Trusted Release（Skill v2.4.1 安全验证状态 + 10% Canary 圆环）

### 2.3 规模闸门评估（铁律 7）

若将七大能力域全部做成完整功能页面，折算模块数 ≥ 7，远超单次交付 3-4 模块上限 → **必须分期**。

| 折算项 | 模块当量 | 说明 |
|---|---|---|
| 总览 Dashboard 主体（8 大功能区 UI + 布局） | 1.5 | 同一页面/同一路由下的功能区块，非独立模块 |
| 实时数据模拟引擎（时钟/Trace 流/测试进度/状态流转） | 1 | Dashboard 的「活」灵魂 |
| 数据表 ×2（工作流 + Trace）+ SDK 双向同步 | 1.5 | 在线存储与双向同步 |
| 分导航占位页 ×5（能力接入/仿真测试/端侧 Runtime/安全合规/发布运营） | — | 轻量占位（路由可达 + 能力域说明卡），不计满模块 |
| **合计** | **≈4** | **符合上限，可动工** |

**分期方案**：
- **本期（Phase 1 · MVP）**：总览 Dashboard 一比一复刻（设计稿像素级还原）+ 数据模拟引擎 + 两张数据表双向同步 + 5 个能力域占位页 + AI Copilot 交互面板
- **Phase 2（对齐原方案 3-6 个月）**：能力接入页完整版（Contract 编辑器/影响分析/批量导入）、仿真测试页（场景库/沙箱配置/真机集群管理）、DAG 可视化回放器
- **Phase 3（对齐原方案 6-12 个月）**：Vibe Coding 工具链（NL 生成 Skill/Contract/编排）、自然语言 Debug 助手（接真实 LLM）、评测闭环、跨角色审批工作流

## 3. 本期需求规格（Phase 1）

### 3.0 Phase 1 功能清单（当前实现）

Phase 1 在保留 Phase 0 全部视觉规格的基础上，补齐了商业化产品的地基：

| 域 | 能力 | 对应接口 |
|---|---|---|

| 多租户隔离 | 所有业务数据以服务端注入的 userId 为前缀 | — |
| 工作流 | CRUD 五端点 + 全量入参校验 | `/api/workflows*` |

### 3.2 非功能需求

| 类别 | 要求 |
|---|---|
| 视觉还原 | 与设计稿逐区域对照：布局结构、配色、字号层级、圆角、间距、图标形状一致 |

| 响应式 | ≥1280px 三栏（左导航 200px + 主区自适应 + 右栏 320px）；768-1280px 右栏下移为两栏网格；<768px 单列堆叠 + 左栏收起为抽屉；按钮点击区 ≥44px；输入字号 ≥16px |
| 兼容性 | 现代 Chrome/Safari/Edge；ES5 语法编写 SDK 相关代码；无 SDK 环境可静态运行 |
| 性能 | 首屏渲染 <1s（本地资源）；模拟引擎定时器合并，无内存泄漏（trace 列表上限截断） |
| 代码架构 | 函数调用链单向无环（DAG）；统一刷新入口 refreshAll()；渲染函数严禁互调 |
| 数据安全 | 清空/危险操作二次确认；演示数据不预填真实隐私 |

## 4. 明确不做（本期边界）

- 不做真实后端/真实设备接入（真机集群、NPU profiling 为 Phase 2+）
- 不做账号体系与多用户权限（个人工作台定位）
- 不做浏览器系统通知推送
- 不做视频/大文件存储
- 5 个能力域子页面为「导航可达 + 能力说明」占位，不承载完整功能（见分期规划）
