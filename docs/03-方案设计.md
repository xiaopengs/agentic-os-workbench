## 2. 布局结构（三栏 Grid）

```
body（--bg 底色）
 └─ .app（grid: topnav 跨 3 列；sidenav | main | aside）
     ├─ header.topnav（60px，白底，sticky）
     ├─ nav.sidenav（208px，白底，含品牌卡）
     ├─ main.main（--bg，padding 24px，含总览页 + 5 个能力域页）
     └─ aside.aside（328px，无底色，4 张卡片纵排）
```

- 断点：`<1280px` aside 移到 main 下方（卡片改 2×2 网格）；`<900px` 单列 + sidenav 汉堡抽屉
- 移动端：KPI 4→2 列、Lifecycle 6 节点纵向时间轴、Simulation Lab 纵排、工作流卡纵排

## 3. 逐区域实现方案

### 3.1 顶部导航（topnav）
- 左：Logo（SVG 三角山形，绿色渐变）+「Agentic OS」18px/800
- 中：6 个导航项，选中态 = 深色（#1a1f24）胶囊白字；其余灰字 hover 变深
- 右：搜索框（--bg 底胶囊、放大镜 SVG、placeholder「搜索 Agent / Skill / Contract / Trace」）、Dev 环境选择器（圆形靶心图标+文字+下拉箭头，点击弹出 Dev/Test/Prod 菜单）、铃铛（右上绿点徽标，点击下拉通知面板 = Attention 3 条）、头像（SVG 机器人）

### 3.2 左侧边栏（sidenav）
10 项，每项 = 图标（16px SVG）+ 文字（13px），选中态：--green-bg 底 + --green-deep 字 + 左侧无额外指示（与稿一致为整行浅绿圆角块）。底部品牌卡：浅绿渐变底圆角卡 + 3D 立方体 SVG 插画 + 「Agentic OS」+「让 AI 代理真正落地」+ 3 个分页圆点（第 1 个实心）。

### 3.3 页头
面包屑「Agentic OS / 工作台」（12px 灰）→ H1「Automation Workbench」（30px/800）+ 绿色浅底胶囊徽标「全链路开发与验证」（同步状态指示器并入此行右侧：●已同步/同步中/离线模式）。

### 3.4 KPI 统计卡（M2）
4 列网格（间距 16px）。每卡：左 44px 圆角方图标（四色体系）+ 中列（数字 30px/800，下方 12px 灰「较上周」）+ 右上角「↗ 12%」（绿色，0% 为灰色）+ 右下角「>」跳转箭头。数据由 `state.kpi` 驱动，Running Tests 数值绑定模拟引擎运行状态。

### 3.5 Agent Lifecycle（M3）
- 标题行：「Agent Lifecycle」17px/700 + 副标题「从意图到发布全链路自动化」
- 6 节点 flex 均分：每节点 = 图标圆（64px 白底，外圈 2px 彩色描边 + 8px 光晕 ring）→ 名称 14px/700 → 两行 11px 灰说明 → 状态胶囊
- 图标配色轮换：绿/绿/紫/绿/蓝/深绿；连接：节点间 24px 虚线 SVG 箭头（用 ::after 或独立 SVG）
- 背景装饰：绝对定位 SVG 淡绿波浪曲线（2 条，opacity .25）+ 散点（6-8 个小圆，绿/紫/蓝，opacity .3-.5）
- 状态胶囊五态：●已完成（绿）、Mock Ready（紫）、24 tests（蓝）、●进行中（绿）、Canary 10%（紫）

### 3.6 Simulation Lab（M4）
- 标题行 + 右侧环境胶囊「◉ Android 14 · Pixel 7」（绿浅底）
- 主体两栏：左 150px 手机模型（CSS：黑边框圆角 26px 机身、内屏紫粉渐变、顶部「10:24」白字 22px、底部栏「📱 Pixel 7」白字胶囊）+ 右侧 2×2 指标卡（每卡：图标+名称 12px 灰 → 大数 22px/700 + 趋势箭头绿）
  - Memory（青水滴）1.8GB ↓18% ｜ NPU（紫芯片）72% ↑6% ｜ P95（蓝闪电）184ms ↓22% ｜ Power（绿电池）1.2W ↓15%
  - 数值波动：每 2s 在基线 ±3% 内随机微调（内存 ±0.1GB、NPU ±2、P95 ±6ms、功耗 ±0.1W），趋势箭头保持
- 测试进度行：5 项横排（<900px 换行 3+2）。每项 = 28px 状态圆 + 名称 12px + 计数 12px：
  - 编译构建 2/2（实心绿勾圆）、单元测试 24/24（实心绿勾圆）、性能测试 12/16（SVG 环 75% 绿）、场景回归 8/12（SVG 环动态）、结果分析（灰空心圆「待开始」）
- 底部运行条（浅灰底圆角行）：绿色播放方钮（40px）+ 计时 00:12:36（mono，每秒+1）+「运行中：场景回归测试」12px + 弹性进度条（绿色，按回归进度）+「↻ Replay DAG」白底按钮 +「⋯」
- Replay DAG 交互：点击 → 场景回归重置为 8/12 重新推进、trace 流重放初始 4 条、toast「DAG 回放已启动」

### 3.7 Live Trace（M5）
- 标题行 + 右侧 mono 时钟（每秒真实走时）+ ⋮
- 行结构（4→6 条，新条目插入顶部 + fadeIn 动画）：彩色圆角方图标 40px → 列（上行 11px 灰类型名，下行 13px/600 Span 名）→ 时间戳（mono 12px 灰）→ 耗时（12px/600）→ 弹性进度条（绿色，宽度按耗时归一化 40-64ms 区间映射）→ Success 绿胶囊
- 新 Span 产生（每 4s）：类型/名称从预置池轮换（含 file_transfer、task_router、npu_infer、calendar_api、route_plan…），耗时 40-220ms 随机，时间戳取当前时钟；同时 addRecord 写入 Trace 表（节流）
- 底部「View full trace →」12px 灰链接 → 切换到 Trace 占位页

### 3.8 Recent Workflows（M6）
- 标题行 + 右上「全部工作流 →」
- 3 列卡（<1100px 纵排）：头部 = 彩色圆角方图标（绿文件夹/蓝日历/橙外卖）+ 名称 14px/700 + 分类 11px 灰 + 右上状态胶囊（运行中=绿浅底动态点；已完成=灰绿底勾）
- 元信息行：设备图标+「3 设备」、步骤图标+「12 个步骤」、圆环图标+「覆盖率 96%」（12px 灰，SVG 小图标）
- 底部：细进度条（按覆盖率）+「Regression 18 min」（11px 灰）
- 「▶ 运行新工作流」按钮（标题行右侧，主绿）：弹出场景模板选择（预置 3 个模板：消息智能摘要/相册整理 Agent/会议纪要生成）→ 写入表 W（addRecord）→ 列表首位刷新

### 3.9 右侧栏（M7）
**AI Copilot**：头部绿色机器人圆头像 +「AI Copilot」15px/700 +「● Online」绿 + ⋮；2×2 按钮（44px 高，白底 --r-el）：生成 Skill（紫立方体）/ 生成 Contract（绿文档）/ 运行回归（蓝播放）/ 分析 Trace（青波形）。点击任一 → 打开对话框（M9）：顶部场景标题 + 消息流（模拟「正在分析…」→ 生成结果卡片：Skill 名/Contract 字段/回归结论/Trace 根因摘要）+ 底部输入框（输入后回显 + 固定智能回复）。历史存 localStorage。

**Attention**：铃铛 SVG +「Attention」+ 右侧圆形数字 3。3 条列表（红警告三角「Contract 变更影响 3 个 Skill」/2小时前；绿勾圆「Skill v1.8 安全验证完成」/4小时前；黄警示「NPU 延迟超过 P95 基线」/5小时前），每条右侧「>」。

**Next Step**：闪电 SVG + 标题 + 数字 4。垂直步骤条：① Mock 联调（绿勾圆）② 场景回归（绿色加载旋转圈）③ 安全扫描（灰圈 3）④ 灰度发布（灰圈 4），步骤间竖虚线。自动流转：场景回归完成 → ② 变绿勾、③ 变加载圈 → 6s 后 ③ 变勾、④ 变进行中 → Canary 从 10% 每轮 +2%。

**Trusted Release**：绿盾牌勾 + 标题 +「?」+ ⋮。左列：Skill v2.4.1（15px/700）+「版本发布」胶囊；3 行验证项（绿勾「安全扫描 通过」/绿勾「兼容性检查 通过」/动态勾「灰度发布 进行中 (10%)」）。右侧 72px SVG 圆环（绿色弧 = canary%）。底部全宽绿色按钮「查看发布详情 →」。

## 4. 数据接入方案（DataBridge）

- 表 W/T 建表后取得 `databaseId`，硬编码进 HTML（`__SMART_PAGE__.database` 平台自动注入）
- 启动：`getSchema` 取 select options → `query`（表 W 按「更新时间」倒序；表 T 按「时间戳」相关字段）分页拉全量（startCursor 链、guard≤100）→ 写入 state → refreshAll
- 写入：新 trace 节流 addRecord（≥4s）；运行新工作流 addRecord 成功后本地插入首位
- 绑定标记：工作流卡片承载字段、trace 行承载字段的最内层元素加 `data-sp-bindable="database"` + `data-sp-database-id`
- 降级：无 SDK/失败 → 演示数据（与设计稿数值一致）+ localStorage 徽标「离线模式」

## 5. 模拟引擎方案（Engine）

| 定时器 | 周期 | 职责 |
|---|---|---|
| tickClock | 1s | Trace 时钟 +1s（局部 DOM 更新）；Simulation Lab 计时 +1s；NPU/内存微调 |
| tickTrace | 4s | 产生新 Span → unshift state.traces（截断至 6）→ addRecord → refreshAll |
| tickProgress | 2.5s | 场景回归 +1/12 → 完成 12/12 时：NextStep 流转、Running Tests 变化、结果分析启动；canary 每 3 轮 +2%（上限 25%） |

暂停策略：页面切到能力域占位页时引擎降频（tickTrace/tickProgress 跳过 DOM 无关节），返回总览恢复。

## 6. 构建与交付

1. 建表 ×2（database-first，Agent 生成 16 位 options id）
2. 写 HTML：骨架（CSS 全量 + HTML 结构）→ 增量 JS ×3 批
3. 自检：lint_schema → lint_database_sdk_usage → lint_page_quality → 铁律 10 冒烟清单
4. `import_html.py` 上传（--databases 绑定两表）→ 表挂载到页面节点
5. `publish_page.py` 发布 → 交付双链接（编辑态 /space/d/ + 发布态 workbuddy.link）
6. 测试用例逐项执行与修正记录见 [04-测试用例与对比修正报告](./04-测试用例与对比修正报告.md)
